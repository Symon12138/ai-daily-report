🥇book-to-skill — 把技术书变成 Agent 随时能调用的技能，不用再把整本书塞进上下文⭐ 34,665
virgiliojr94/book-to-skill

它解决的是「书只读了一遍、三个月后忘了第七章讲过什么」：指向一个 PDF/epub/docx/rtf 文件、一个资料文件夹或一串 glob，它会蒸馏出一份结构化技能——核心心智模型与章节索引（SKILL.md，约 4 千 token）、每章一个按需加载的文件（各约 1 千 token）、按字母排序并标注章节出处的术语表、以及全部技法与反模式的模式库。它明确不做「摘要式总结」，而是抽结构，之后你只打一句「/书名 关键词」，Agent 就去读对应章节、按原文回答，不靠模型瞎编。遵循 Agent Skills 开放标准，GitHub Copilot CLI、Amp、Claude Code、Codex、Hermes Agent、OpenCode、OpenClaw 读的是同一份 SKILL.md；对 Hermes Agent 会按分类装进个人技能目录。官方实测：回答同一个问题时，比把整本书灌进上下文省 24–51 倍 token。

用途：把读过一遍的技术书、内部规范、资料合集沉淀成 Agent 能长期反复调用的能力，写代码、做方案时随手一问就取回原文依据 · 亮点：近一周持续提交，10 月 11 日一天连修 7 处提取可靠性问题（康熙部首归一到对应汉字、拒绝畸形 BOM 编码输入、校验 Markdown 代码围栏闭合、保留 RTF 转义控制字面量、波斯语 ZWNJ 序数、首章标题之前的正文可达性）；v1.4.0 一次修掉 6 处「静默丢内容 / 静默答错」，扫描版 PDF 现在约 0.01 秒快速失败并提示先用 ocrmypdf；MIT 许可，pip 装完用 book-to-skill 命令行即可 · 适合：买了不少技术书、想让它真正变成干活时能查的东西的人

🥈PageIndex — 不用向量库的长文档检索：让模型像人一样翻目录，找到对的那一页⭐ 39,083
VectifyAI/PageIndex

向量检索按「语义相似」捞段落，但相似不等于相关——专业长文档真正需要的是相关性，而相关性要靠推理。PageIndex 把向量索引换成层级树索引：第一步给每份文档生成树结构，第二步让 LLM 沿树推理着检索，像人类专家那样直接翻到报告里该读的那一节；结果能追溯到明确的节点与页码，可解释、可核对，不做切块、不建向量库。

用途：财报、研报、标准、长论文这类「必须找对那一页」的场景，问一句就拿到带出处的答案 · 亮点：10 月 12 日发布 v0.4.0，官方称「现在建 PageIndex 比建向量索引更便宜」——pip install -U pageindex 一条命令就带本地模式：索引、检索、问答全在自己机器上跑，用自己的 LLM key，不需要服务器、不需要向量库、也不需要 PageIndex 的 API key，同一套 client 也能指向云端；Flash 引擎改用版面统计直接生成树结构，生成结构本身不调 LLM，只有节点摘要是模型写的，树扩展并发提议一批节点，索引速度大幅提升；同日还把默认索引与对话模型换成 gpt-6-luna / gpt-6-sol；MIT 许可 · 适合：被向量库检索准确率折磨过、又不想维护一整套 RAG 基础设施的人
